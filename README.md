# learning-springboot スキル

Javaの基礎を終えた人が、SpringBootでのWeb開発を段階を踏んで身につけていくための
Claude Code用スキルです。代わりに実装する相手ではなく、一緒に振り返って次の一歩を
示すメンターとして動きます。

学習コードの代筆はしません。頼まれてもやりません。代筆したくなる場面というのは、
ヒントの出し方か、参考資料の示し方か、人への聞き方のどこかがうまくいっていない場面です。
代筆するとその不具合を隠したまま先へ進んでしまいます。行き詰まったときは穴を埋めずに、
記録に残して次へ活かします。例外はひとつだけで、ポート競合やビルドエラー、依存解決の
失敗といった、学習項目ではない環境設定のトラブルシューティングです。

ヒントの出し方もわざと遅くしてあります。わからないと伝えるだけでは次の段階に進みません。
何を調べて、何を試して、どうなったかを返すのが前提です。それでも解決しないときは、
AIが答えを出すより先に人間のメンターへ相談するよう促します。相談文の下書きは用意します。
不親切にしているわけではなく、調べる力と質問する力そのものを学習項目に入れているからです。

このフォルダを対象プロジェクトの`.claude/skills/`配下に置けば、他のプロジェクトでも
そのまま動きます。コピーでも git clone でも構いません。やり方は[導入方法](#導入方法)に
書きました。特定のアプリのコードには依存していません。

## 中身

```
learning-springboot/
├── README.md                        このファイル
├── SKILL.md                         スキル本体。振る舞いの定義
└── references/
    ├── curriculum-template.md       汎用カリキュラムのひな形。Step0〜36と依存関係マップ。
    │                                Step番号は変わりうるので正確な範囲は目次を参照
    ├── faq.md                       学習者とのやり取りから溜めていくQ&A集
    └── maintainer-notes.md          スキル保守者向けメモ。学習セッション中には読まない
```

## 導入方法

置き方は2つあります。スキル側の更新を受け取りたいなら方法Bの git clone を選んでください。
方法Aだと、更新のたびに手でコピーし直すことになります。

| | 方法A コピー | 方法B git clone |
|---|---|---|
| 初期導入 | フォルダをコピー | スキルだけを clone |
| 更新 | もう一度コピーして上書き | `git pull` 一発 |
| 向いている場面 | ネットワークが制限されている、一度きりの利用 | ふだんの研修利用 |

### 方法A フォルダをコピーする

このフォルダごと、対象プロジェクトの `.claude/skills/` 配下にコピーします。

```bash
cp -r learning-springboot /path/to/target-project/.claude/skills/
```

更新は、新しいものを取得して同じ場所に上書きするだけです。ただし `references/faq.md` に
溜めた内容は上書きで消えます。残したいならコピーする前に退避してください。

### 方法B git clone でスキルだけ取得する

対象プロジェクトのルートで、スキルのリポジトリを `.claude/skills/` 配下へ直接cloneします。
アプリのリポジトリとは別のリポジトリとして並ぶので、アプリ側の履歴を触らずに
スキルだけ更新できます。

```bash
git clone https://github.com/AsamiShingo/learning-springboot .claude/skills/learning-springboot
```

`--depth 1` を付けると履歴を持たない軽いクローンになります。更新は同じく `git pull` です。

```bash
git clone --depth 1 https://github.com/AsamiShingo/learning-springboot .claude/skills/learning-springboot
```

#### スキルを更新する

対象プロジェクトのルートで次を実行します。

```bash
git -C .claude/skills/learning-springboot pull
```

カリキュラムを調整するときは `.claude/state/learning-springboot/CURRICULUM.md` 側を
書き換えてください。スキル本体の `references/curriculum-template.md` などを直接いじると
`pull` が競合します。

モード7でFAQに追記した内容は、cloneした作業ツリーの未コミット変更として残ります。
そのままだと `pull` が競合することがあります。追記を残すならコミットしてから `pull` して
ください。他の学習者にも共有したいなら fork して push します。捨ててよければ
`git -C .claude/skills/learning-springboot checkout -- references/faq.md` で戻せます。

### .gitignore の設定

方法Aでも方法Bでも設定します。スキル本体と学習者個人の進捗ファイルを、アプリのリポジトリに
コミットしないよう除外します。対象プロジェクトの `.gitignore` に2行足してください。

```gitignore
# 学習支援スキル本体。別リポジトリで管理する。アプリの資産ではない
/.claude/skills/learning-springboot/
# 学習の進捗ファイル。学習者個人のもの
/.claude/state/
```

方法Bでは特に外せません。cloneしたディレクトリの中に `.git` があるため、除外しないと
`git add` のときに embedded git repository の警告が出て、中身が追跡されないまま
コミットされてしまいます。

`.claude/state/` のほうは、初回にスキル側から追加してよいか聞かれます。そこで許可すれば
手で書く必要はありません。

すでにコミットしてしまった場合、`.gitignore` に書くだけでは追跡が外れません。次のコマンドで
追跡を解除してからコミットしてください。ファイル自体は消えません。

```bash
git rm -r --cached .claude/skills/learning-springboot .claude/state
```

なお `.claude/` をまとめて除外するのは避けてください。settings.json のようにチームで
共有したい設定も同じ階層に入ります。

### 置いたあとの流れ

1. 対象プロジェクトでClaude Codeを起動して、こう話しかけます。

   ```
   learning-springbootスキルを使って、今の状況を教えて
   ```

   学習相談や進捗確認、コードレビューの流れであれば、Claudeが自分でこのスキルを
   選ぶこともあります。

2. 初回にClaudeが2つ確認します。`.claude/state/learning-springboot/CURRICULUM.md` が
   無ければ `references/curriculum-template.md` をもとに作ってよいか。
   `.claude/state/learning-springboot/PROGRESS.md` が無ければ空の進捗テーブルを
   作ってよいか。どちらも許可すれば `.claude/state/learning-springboot/` 配下に
   カリキュラムと進捗管理表ができて、以降はそれを見ながら進みます。カリキュラムの内容は
   プロジェクトの事情に合わせて後から変えられます。プロジェクト本来のドキュメント置き場である
   `docs/` には何も作りません。git管理下のプロジェクトなら、`.gitignore` に
   `.claude/state/` を追加して進捗ファイルをコミット対象から外してよいかも聞かれます。

3. 最初のStepに入る前に、作るアプリの題材を決める対話があります。何を管理するアプリに
   するかは自由です。業務で扱っている題材でも趣味の題材でも構いません。ただしその前に
   Claudeから一度、その題材でカリキュラム全体を通した学習ができるか、次の3点を一緒に
   確認されます。

   - 主となるデータのほかに、関連するデータが1つ以上あるか。本に対する著者や貸出記録のような
     関係です
   - 一覧を検索したり並び替えたりできる属性が複数あるか。タイトル、カテゴリ、登録日など
   - 使う人に2種類以上の役割を想定できるか。一般利用者と管理者など

   後半のStepでは関連データの扱いや検索・ページング、ログインと権限を扱います。題材が
   単純すぎるとここが体験できません。とはいえ満たさない題材が却下されることはなく、
   この題材だと何が体験できないので何を足しませんか、という形で補強が提案されます。
   決まった題材は `CURRICULUM.md` の冒頭に記録され、以降のStepではその題材に沿った
   機能案が、Entity名や画面名まで含めた形で毎回出てきます。

## 使い方

| やりたいこと | 話しかけ方の例 |
|---|---|
| 全体の進み具合を見る | 「今の状況見せて」「別のステップからやりたい」 |
| 次に何をやるか決める | 「次何すればいい?」「Step5から始めたい」 |
| 実装中に詰まった | 「わからない」「ヒントが欲しい」 |
| 書いたコードを確認したい | 「レビューして」「このステップ終わったか確認して」 |
| ステップを完了として記録したい | 「Step4完了にして」 |
| チームに進捗を共有したい | 「進捗をチームに共有して」 |
| 全部終わったか確認したい | 「修了できるか確認して」 |
| 今のやり取りを後で活かせるようにしたい | 「この質問と回答をFAQに残して」 |

Claudeはこれらを8つのモードとして扱います。判断基準は `SKILL.md` にあります。

0. 全体状況確認。`.claude/state/learning-springboot/PROGRESS.md` の一覧と依存関係マップを
   見せます。どのStepへ移りたいかは学習者の意向を尊重します。
1. スタート確認。選んだStepの目的と完了条件を示します。初めて出てくる概念には、読むべき節まで
   指定した参考URLを添えます。既習の応用なら概念名を挙げるだけに留めて、だんだん手を離します。
   メンターがコード例を書いて見せることはしません。
2. 実装中の質問対応。いきなり答えは出しません。まず概念名と参考URL、次に該当するコード箇所、
   最後に文章での方針説明、という順でヒントを足していきます。次の段階へ進むには、何を調べて
   何を試してどうだったかの報告が必要です。わからないの一言では進みません。コード箇所を
   示しても解決しないときは、方針説明よりも先に、相談文の下書きを添えて人間のメンターへの
   相談を促します。それでも解決しなければ方針説明に移り、さらに範囲を絞って一緒に手を
   動かします。どの段階でも、行き詰まった内容そのものを記録に残します。
3. 完了レビュー。完了条件を満たしたかだけでなく、コードの書き方、過去Stepとのつながり、
   別の設計案についても話します。
4. 完了処理。`.claude/state/learning-springboot/PROGRESS.md` の該当行を完了に更新します。
   進捗管理はこのファイルだけで行い、gitのコミットやタグ付けは提案しません。学習状態の管理と
   gitでの資産管理を混ぜないためです。
5. チーム進捗の共有。頼まれたら、現在Stepと Step0の実証スコアだけを要約した短いテキストを
   作ります。Teamsでもメールでも口頭報告でも、そのまま使える長さです。ファイルへの書き込みや
   送信はしません。学習者ごとにアプリとスキルのコピーが別々のgit管理下にあるので、
   ファイル経由の自動集約はそもそも成り立ちません。
6. 修了確認。カリキュラムの修了基準を満たしているかを判定します。記録を鵜呑みにせず、
   リポジトリを実際に読んで確かめてから修了報告の要約を作ります。
7. FAQ化。頼まれたら、質問と回答を個人情報や機密情報が残らない形に一般化して
   `references/faq.md` に足します。以降の学習相談で参照されます。

公式ドキュメントなどの参考URLは、あらかじめリンク集として持たせていません。技術情報は
古くなるのが早いので、そのときの質問に応じてClaudeがWeb検索して示します。

## セッションを跨いだ引き継ぎについて

詰まったまま解決しなかったことや、レビューで見つかった未対応の点は、`PROGRESS.md` の
宿題という欄にClaudeが自動で書き込みます。次にこのスキルを呼び出したとき、Claudeはこの欄を
読んで前回どこで止まっていたかを把握してから話し始めます。学習者側で何かを管理したり
書式を意識したりする必要はありません。前回の続きからと言えば、それだけで前回の行き詰まりを
踏まえた対応になります。

## FAQの蓄積について

`references/faq.md` は、学習者とのやり取りから溜まっていく質問と回答のまとめです。
個人の進捗である `.claude/state/` とは違い、将来の学習者にも渡したい知識なので、
スキル本体側に置いています。自動では溜まりません。この質問と回答をFAQに残して、と
はっきり頼んだときだけ、Claudeが個人や会社固有の情報を落としてから追記します。
詳しくは SKILL.md のモード7を見てください。

溜まったFAQは、以降の学習相談で自動的に参照されます。

## カスタマイズ

`references/curriculum-template.md` にあるStepの数や順序、完了条件はひな形です。
`.claude/state/learning-springboot/CURRICULUM.md` を作ったあとなら、対象プロジェクトの
技術スタックや学習方針に合わせて自由に編集して構いません。

特定プロジェクトの実際の開発履歴を教材に使いたい場合は、`docs/LEARNING_ROADMAP.md` の
ようなファイルを別に用意すると、このスキルが参考資料として読みます。無ければ無視します。
これはプロジェクト本来のドキュメントなので、`.claude/state/learning-springboot/` ではなく
`docs/` に置いたままで構いません。

## 学習者個人の状態について

`.claude/state/learning-springboot/` 配下の `CURRICULUM.md` と `PROGRESS.md` は、
学習者ごとの個人的な進捗管理ファイルです。`docs/` には一切作りません。

スキル本体の `.claude/skills/learning-springboot/` の中に置かないのは、スキル本体が
チームやコミュニティで共有・更新される対象になりうるからです。git管理、submoduleでの
取り込み、pluginとしての配布や再インストールなどが起こります。個人の進捗をスキル本体の
ディレクトリに置くと、スキルを更新するたびに上書きされたり消えたりします。だから進捗は
`.claude/skills/` とは別系統の `.claude/state/` 配下に分けて置きます。

複数の学習者が同じベースアプリを個別にクローンやフォークして使っても、それぞれの
`.claude/state/learning-springboot/` 配下に収まります。プロジェクト本来のドキュメントや
スキル本体と混ざることはありません。

進捗ファイルはコミット対象から外す前提です。このディレクトリが実際に作られるタイミングで、
git管理下のプロジェクトであれば、Claudeが `.gitignore` に `.claude/state/` の行を
追加してよいか確認します。許可すれば自動で追加されるので、うっかりコミットしてしまう心配は
ほぼありません。スキル本体もアプリの資産ではないので、同じく `.gitignore` で除外することを
おすすめします。書き方は上の[.gitignore の設定](#gitignore-の設定)にあります。

## 前提

Claude Codeを使うこと。それと、`.claude/state/learning-springboot/` 配下の
`CURRICULUM.md` と `PROGRESS.md` を作成・編集する権限。進捗管理はこの2ファイルで完結し、
コミットやタグ付けといったgit操作は前提にしていません。
